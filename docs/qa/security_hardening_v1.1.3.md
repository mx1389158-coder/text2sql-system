# Evaluation and deployment hardening (v1.1.3)

Verified on 2026-11-06 (Asia/Shanghai).

## Evaluation authorization

- `POST /api/v1/evals/run`, `GET /api/v1/evals/{job_id}` and `GET /api/v1/evals`
  require the authenticated API key to resolve to the exact `evaluation` scope.
- A valid key in `restricted_analyst`, `analyst`, `finance_admin` or `default` receives HTTP 403.
- Evaluation jobs persist an immutable owner scope. Repository `get`, `list`, `update` and recovery
  operations all include that scope; cross-scope detail reads return 404.
- Jobs created before the scope migration receive `__legacy_unscoped__` and are not exposed or
  recovered as `evaluation` jobs.
- Job creation uses a SQLite `BEGIN IMMEDIATE` transaction to enforce
  `TEXT2SQL_MAX_ACTIVE_EVALUATION_JOBS` atomically across API workers. The default is one active
  queued/running job; excess requests receive HTTP 429 with `Retry-After: 5`.

New deployments generated by `scripts/generate_deployment_secrets.py` receive separate random
`default` and `evaluation` API keys in `TEXT2SQL_API_KEYS_JSON`. A deployment using only
`TEXT2SQL_API_KEY` remains valid for ordinary query APIs, but evaluation APIs intentionally remain
unavailable until a scoped evaluation key is configured. Existing deployments can run
`python scripts/ensure_evaluation_auth.py --env-file .env`; it preserves the current key as the
`default` key, adds a random evaluation key, updates the file atomically and prints no secret.

## Deployment boundary

- Compose no longer contains fallback PostgreSQL passwords. Both `POSTGRES_ADMIN_PASSWORD` and
  `TEXT2SQL_READONLY_PASSWORD` are required during Compose interpolation.
- PostgreSQL, Redis and the direct API host port bind to `TEXT2SQL_BIND_HOST`, which defaults to
  `127.0.0.1`.
- The Web/Nginx entry point remains separately configurable through `TEXT2SQL_WEB_BIND_HOST` and
  defaults to `0.0.0.0`; `/api/` is proxied to the API over the private Compose network.
- Publishing an internal port on `0.0.0.0` now requires an explicit deployment override.

## Input and SQL guard fixes

- API query and evaluation strategies use `Literal["baseline", "optimized"]`; invalid values
  receive HTTP 422 before orchestration begins.
- Restricted policies reject wildcard result projections (`SELECT *` and `SELECT alias.*`) without
  rejecting aggregate arguments such as `COUNT(*)`.
